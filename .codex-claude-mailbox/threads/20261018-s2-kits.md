# Goal

依 user 2026-10-18 核准的四項建議，將場域系統 S2 以最低耦合拆成本專案的 Kit，產品線可選，並新增參數設定步驟與 runtime-settings-kit。完整計畫見 `docs/s2-kit-split.md`。

# Claude Notes

## 工作方式

- 分支 `feature/s2-kits` 自 `main`（6ffb6f3）建立。建立當下另一個工作階段正在 `feature/example-scenario` 有未提交的程式變更，因此不切換工作目錄，以 git 底層指令（暫存 index + commit-tree）直接建立 commit，工作目錄未被改動。
- 決策暫編 D-A1 至 D-A4，合併到 main 時接續 decision-log 編號，避免與平行分支衝突。本分支未修改 decision-log、mailbox index 與 GUI 讀取的設定檔。

## WP1 結果

- 新增 `kits/entry-permission-kit/`：manifest、kit.contract.json（含 auth、input、output、errors、sideEffects）、kit.definition.json、安裝腳本、README、後端原始碼（roles、entry_points、entry_point_overrides、user_scopes、user_read、login_guard、security、passwords、deps、routes_auth、routes_users、三個 model、兩個 schema）與測試。
- Passed: `PYTHONPATH=kits/entry-permission-kit/src/backend python3 -m unittest discover -s kits/entry-permission-kit/tests -v`（14 tests OK，Python 3.10.12）
- 去識別化：以本機詞彙清單搜尋新增檔案，結果為零。
- 未涵蓋：API 端點整合測試（環境無 FastAPI、SQLAlchemy）、前端、GUI 登錄、組裝驗證。

## WP4 結果：product-process-kit

- 分支 `feature/product-process-kit`（接在 `feature/param-settings-step` 之後）。新增 `kits/product-process-kit/`：manifest、契約（7 個 API、4 個 Python 能力）、definition（7 個子功能）、安裝腳本、README、產線定義範例（含 2 條預留產線）、後端原始碼與測試。
- 通用化：行業專屬欄位改為 `attributes` 與 `recipe_lines`；有鉛／無鉛改為 `process_variant`；稽核角色隱藏欄位改為每個項目的 `hidden_from_roles`；異動紀錄不跨 Kit 建外鍵。
- Passed: `PYTHONPATH=kits/product-process-kit/src/backend python3 -m unittest discover -s kits/product-process-kit/tests`（16 tests OK）；`PYTHONPATH=kits/entry-permission-kit/src/backend python3 -m unittest discover -s kits/entry-permission-kit/tests`（14 tests OK）。
- 模型與路由只做語法編譯，沒有 API／資料庫整合測試（環境沒有 FastAPI、SQLAlchemy）。
- 去識別化：以本機詞彙清單搜尋新增檔案，結果為零。
