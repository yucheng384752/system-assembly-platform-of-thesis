# Goal

依 user 2026-10-18 核准的四項建議，將場域系統 S2 以最低耦合拆成本專案的 Kit，產品線可選，並新增參數設定步驟與 runtime-settings-kit。完整計畫見 `docs/s2-kit-split.md`。

# Claude Notes

## 工作方式

- 分支 `feature/s2-kits` 自 `main`（6ffb6f3）建立。建立當下另一個工作階段正在 `feature/example-scenario` 有未提交的程式變更，因此不切換工作目錄，以 git 底層指令（暫存 index + commit-tree）直接建立 commit，工作目錄未被改動。
- 決策暫編 D-A1 至 D-A4，合併到 main 時接續 decision-log 編號，避免與平行分支衝突。本分支未修改 decision-log、mailbox index 與 GUI 讀取的設定檔。

## WP1 結果

- 新增 `kits/entry-permission-kit/`：manifest、kit.contract.json（含 auth、input、output、errors、sideEffects）、kit.definition.json、安裝腳本、README、後端原始碼（roles、entry_points、entry_point_overrides、user_scopes、user_read、login_guard、security、passwords、deps、routes_auth、routes_users、三個 model、兩個 schema）與測試。
- Passed: `PYTHONPATH=kits/entry-permission-kit/src/backend python3 -m unittest discover -s kits/entry-permission-kit/tests -v`（14 tests OK，Python 3.10.12）
- 去識別化：以本機詞彙清單搜尋新增檔案，結果為零。
- 未涵蓋：API 端點整合測試（環境無 FastAPI、SQLAlchemy）、前端、GUI 登錄、組裝驗證。

## WP4 結果：product-process-kit

- 分支 `feature/product-process-kit`（接在 `feature/param-settings-step` 之後）。新增 `kits/product-process-kit/`：manifest、契約（7 個 API、4 個 Python 能力）、definition（7 個子功能）、安裝腳本、README、產線定義範例（含 2 條預留產線）、後端原始碼與測試。
- 通用化：行業專屬欄位改為 `attributes` 與 `recipe_lines`；兩組製程區分改為 `process_variant`；稽核角色隱藏欄位改為每個項目的 `hidden_from_roles`；異動紀錄不跨 Kit 建外鍵。
- Passed: `PYTHONPATH=kits/product-process-kit/src/backend python3 -m unittest discover -s kits/product-process-kit/tests`（16 tests OK）；`PYTHONPATH=kits/entry-permission-kit/src/backend python3 -m unittest discover -s kits/entry-permission-kit/tests`（14 tests OK）。
- 模型與路由只做語法編譯，沒有 API／資料庫整合測試（環境沒有 FastAPI、SQLAlchemy）。
- 去識別化：以本機詞彙清單搜尋新增檔案，結果為零。

## WP5 結果：batch-production-kit 第一階段

- 分支 `feature/batch-production-kit`（接在 `feature/product-process-kit` 之後）。新增 `kits/batch-production-kit/`：契約（12 個 API、2 個事件、4 個 Python 能力）、definition（9 個子功能，4 個標示第二階段）、README、後端與測試。product-process-kit 補了 `model_lookup`（型號快照、站點結構、以業務鍵找型號），讓批次不必匯入它的資料表。
- 對外接點只有三個：事件（`MeasurementRecorded`、`BatchChanged`）、閘門（寫入前、站點完成、完成前阻擋）、產品定義查詢。詳見 README。
- Passed: `PYTHONPATH=kits/batch-production-kit/src/backend python3 -m unittest discover -s kits/batch-production-kit/tests`（30 tests OK）；另兩個 Kit 的 16 項與 14 項仍通過。
- 資料表與路由只做語法編譯，沒有 API／資料庫整合測試。去識別化以本機詞彙清單搜尋新增檔案，結果為零。
- 刻意不放進來：重設全部批次資料端點（測試資料清理工具）。

## WP6 結果：alarm-exception-kit

- 分支 `feature/alarm-exception-kit`（接在 `feature/batch-production-kit` 之後）。新增 `kits/alarm-exception-kit/`：三種規則（規格範圍、門檻、一致性）、純函式對帳、異常簽核狀態表、設定載入、事件訂閱與 `ExceptionGate`（order 20）、5 個 API、2 個入口（`alarm_manage`、`exception_decide`）。
- 為此補改 batch-production-kit：閘門多一個 `validate_value`，新增唯讀介面 `batch_read`（可見性、跨欄位數值），路由改用它；契約與定義同步更新，測試 31 項。
- Passed: `PYTHONPATH=kits/alarm-exception-kit/src/backend python3 -m unittest discover -s kits/alarm-exception-kit/tests`（23 tests OK）。資料表與路由只做語法編譯，沒有 API／資料庫整合測試。去識別化搜尋結果為零。
- 尚無前端；`AlarmChanged` 事件留給儀表板 Kit。

## WP7 結果：equipment-maintenance-kit

- 分支 `feature/equipment-maintenance-kit`（接在 `feature/alarm-exception-kit` 之後）。新增 `kits/equipment-maintenance-kit/`：設備與點檢表、期別唯一的點檢紀錄、複核、維修單、月度 CSV 匯出（防公式注入）、`EquipmentCheckGate`（order 10）、13 個 API、3 個入口。
- 批次生產 Kit 是可選相依：啟動時偵測到 `app.core.gates` 才註冊閘門，本 Kit 可單獨使用。
- Passed: `PYTHONPATH=kits/equipment-maintenance-kit/src/backend python3 -m unittest discover -s kits/equipment-maintenance-kit/tests`（22 tests OK）。資料表與路由只做語法編譯，沒有 API／資料庫整合測試。去識別化搜尋結果為零。
- GUI 另開分支 `feature/flow-selection-link`（D-A3）：功能選配步驟顯示由流程畫布帶入的來源，307 項前端測試通過。

## WP8 結果：batch-production-kit 第二階段

- 分支 `feature/batch-production-phase2`（接在 `feature/equipment-maintenance-kit` 之後）。新增入庫單、回鍋確認單、子表格備註、照片佐證，各自的規則為純函式；預設全部關閉，啟動時 `enable_batch_extras(raw, object_store)` 選用。完成條件多一個通用插槽 `completion_checks`。

- Passed: batch-production-kit 49 tests OK（原 31 + 新 18）；其他四個 Kit 的測試仍通過。資料表與路由只做語法編譯，沒有 API／資料庫整合測試。
- 不放進來：回鍋單的來源批次與併入總重計算。
