## 3. 檢視模式

畫布工具列新增一組三選一的檢視切換（`role="radiogroup"`，標籤「檢視」）：「單層」「展開」「疊層」。預設「單層」，即現況。檢視模式是畫面狀態（UI state），不寫進流程文件、不寫入瀏覽器儲存；離開圖或重新載入回到「單層」。

### 3.1 單層（現況加 V4）

進入子流程後，畫布上方（工具列之下、畫布之上）多一列「上一層」：依序顯示上一層圖中引用此子流程的節點的全部前置節點名稱、該節點本身（標示為目前所在）、全部後續節點名稱。沒有前置或後續時顯示「（無）」。這一列只顯示，不可編輯；每個名稱是按鈕，按下回到上一層並選取該節點。最上層的圖不顯示這一列。

### 3.2 展開（V2）

目前這張圖中每個有子流程的節點，原位置改畫成一個外框，框內是它的子流程（遞迴到第 3 層）。外框標題是節點名稱。

- 版面：外框寬高由子圖的 `layout` 範圍加邊距算出。外框右側與下方的同層節點依外框多出的寬高平移，避免重疊。平移只是顯示用的換算，不改 `layout`。
- 拖曳節點後，寫回 `layout` 的是「顯示位置減去該節點當時的平移量與所屬外框的原點」。同一份文件切回「單層」時，每張圖的位置與展開前相同（除了被拖曳的節點）。
- 再按一次（切回「單層」）即收合。

### 3.3 疊層（V3）

- 最上方一列是目前這張圖（業務層的 workflow），節點位置沿用 `layout` 的橫向位置，縱向壓成一列帶。
- 其下每一層深度一列帶：第 2 層列帶放目前這張圖各節點的子流程，各自以外框呈現，橫向對齊它的上層節點；第 3 層列帶同理。上層節點到其子流程外框之間畫一條細的對應線（不是流程連線，不可選取、不可編輯）。
- 下方列帶內同時顯示先後連線（實線）與資料流連線（虛線，第 4 節）。
- 疊層檢視開啟時，在檢視切換旁以 `role="status"` 顯示固定文字「系統邏輯疊層：公司需要，待開發。僅供檢視與編輯流程，不影響計畫與工單。」（V6，契約 8.1 第 4 項）。
- 缺口標示見第 5 節。

### 3.4 展開與疊層中的編輯（V5）

- 每個畫上去的節點都知道自己屬於哪張圖。選取、節點細項、改名、刪除、拖曳、連線都作用在該節點所屬的圖。
- 連線只允許同一張圖內的兩個節點；跨圖連線拒絕並以既有的錯誤訊息區（`role="alert"`）說明「連線只能在同一個流程內」。
- 工具箱的「加入到畫布」與拖放：加入到「目前選取節點所屬的圖」；沒有選取時加入到目前這張圖（最上方那張）。拖放到某個外框內時加入到該外框的圖。
- 節點上限、層數上限、完整性檢查沿用既有函式（`integrityErrors`、`MAX_NODES`、`MAX_DEPTH`、`MAX_GRAPHS`），不另寫一套。
- 鍵盤替代沿用 DESIGN.md：連線以節點細項的核取清單建立；「選取節點」清單在展開與疊層時依圖分組列出全部可見節點。

## 4. 資料流連線（V7）——user 於 2026-11-16 確認，文件升為第 6 版

流程文件 `composer-aov-list` 由第 5 版升為第 6 版。原因：第 5 版的 `schemas/aov.schema.json` 對連線設了 `additionalProperties: false`，加欄位就不再是合法的第 5 版文件；新舊程式對同一版號的語意也會不同（Codex 2026-11-15 審閱指出，Claude 已核對 schema 第 177 至 179 行）。

```ts
export interface GraphEdge { id: string; from: string; to: string; transferMin?: number; kind?: 'dataflow'; formId?: string | null }
```

- `kind` 省略代表先後連線；`'dataflow'` 代表資料流連線，畫成虛線、單段直線、箭頭同色，與疊層的對應線樣式要能區分。
- `formId` 只在資料流連線有意義：這條連線傳遞哪張表單的資料；可為 `null`，代表尚未指定。
- 載入：第 5 版文件無損載入為第 6 版（所有連線都是先後連線）；匯出一律寫第 6 版。第 1 至 4 版既有的升版路徑不變，最後接到第 6 版。
- 驗證（`integrityErrors` 與 schema 兩邊一致）：
  - 資料流連線只能出現在子流程（第 2、3 層），最上層的圖拒絕。
  - 資料流連線的 `formId` 非空時必須存在於 `doc.forms`；不可帶 `transferMin`。
  - 先後連線不可帶 `formId`。
  - 同一對節點可同時有一條先後連線與一條資料流連線；重複判定的鍵要含種類。
  - 連線 id 唯一、端點存在，兩種連線都檢查。
  - 資料流連線可以成環（資料可回傳），成環檢查只看先後連線。
- 集中一個判定函式（例如 `isSequence(edge)`），所有「看先後順序」的地方共用，不各自寫條件。

- `canvasView.ts` 的 `ViewEdge`、`CanvasViewElements.tsx` 的 `flowElements`、`WorkflowCanvas.tsx` 的連線轉換：帶著 `kind` 與 `formId`，畫成虛線。

### 4.4 建立方式

- 節點細項新增「資料來自哪些節點」核取清單（鍵盤替代），每一項可選傳遞的表單（下拉，含「尚未指定」）。只在子流程顯示。
- 畫布工具列在子流程中多一組連線種類切換（「先後」「資料流」，預設「先後」），決定拖曳連線時建立哪一種。最上層不顯示。

## 5. 表單輸入與輸出缺口提示（V6）——user 於 2026-11-16 確認

名稱固定為「表單輸入與輸出缺口」。這是畫布層級的提示，不是契約 8.1 第 5 項的埠位檢查，文件與畫面都不得宣稱已完成該項檢查。

對一個有子流程的節點 P 與它的子流程 C：

| | 上層預期 | 子流程宣告 |
|---|---|---|
| 輸入 | P 在上層圖中「直接先後前置節點」的表單（`formId` 非空者） | C 的「開始」節點發出的資料流連線所帶的 `formId` |
| 輸出 | P 自己的表單（`formId` 非空時） | 指向 C 的「結束」節點的資料流連線所帶的 `formId` |

- 以表單 id 的集合比較。缺口分「缺少」（上層預期、子流程沒有宣告）與「多出」（子流程宣告、上層沒有）。
- 資料流連線的 `formId` 為 `null` 時另列「尚未指定表單 N 條」，不算沒有缺口。
- 有缺口或有尚未指定的外框，在標題旁顯示警示圖示與「缺口 N 項」，可展開逐項列出表單名稱與方向。展開與疊層兩種檢視都顯示。
- 缺口不阻擋顯示、編輯與輸出。
- 已知限制（寫進 DESIGN.md 或說明文字）：只比表單是否相同，不比欄位、型別與版本；P 自己的表單是否也是輸入不在這一版的範圍。
