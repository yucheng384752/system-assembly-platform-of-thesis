# 系統使用範例：去識別化的配料混合產線

日期：2026-10-16
狀態：設計草案，尚未實作；實作前須 user 核定第 5 節的問題。
來源：`docs/aov-merge-inventory.md` 發現 3 所述的實際案例流程。本文件與其衍生資料不得出現來源的公司、專案、產品或設備名稱，也不得出現任何製程數值。

## 1. 目的

讓第一次使用的人在「需要填寫或操作的地方」看到一個合理、但不屬於任何真實客戶的範例，知道該填什麼格式與粒度。範例只引導，不代填、不預設值。

## 2. 去識別化規則

| 類別 | 處理 |
|---|---|
| 公司、專案、分支、提交識別碼 | 全數移除 |
| 產品、原料、設備、容器名稱 | 改為通用名稱（原料 A、原料 B、混合槽等），不保留產業特有用語 |
| 製程數值（門檻、上下限、時間、溫度、壓力、步驟數） | 全數移除；提示文字改為「依貴廠規格填寫」，不給任何數字 |
| 步驟細節（如分多段的操作順序） | 合併為單一通用步驟 |
| 角色名稱 | 使用通用職務（現場操作員、品管人員） |
| 流程結構 | 保留「領料、備料、加工、檢驗、包裝、入庫」這類跨產業的順序，不保留特有的分支與子流程 |

驗收方式：以來源檔案中的專有詞彙、數值逐一搜尋本範例與所有衍生程式碼，結果必須為零。搜尋清單由 Claude 在本機維護，不寫進 repo，避免清單本身洩漏。

## 3. 範例情境：配料混合產線

工廠名稱範例：第一廠
生產邏輯名稱範例：配料混合產線

| 順序 | 節點名稱 | 時機（範例） | 負責職務（範例） | 標準表單 |
|---|---|---|---|---|
| 1 | 開立領料單 | 接到生產工單後 | 生管人員 | 領料單 |
| 2 | 領料 | 領料單核准後 | 倉管人員 | （無獨立表單，不設表單） |
| 3 | 配料 | 領料完成後 | 現場操作員 | 配料紀錄 |
| 4 | 混合 | 配料完成後 | 現場操作員 | 混合紀錄 |
| 5 | 品質檢驗 | 混合完成後 | 品管人員 | 檢驗紀錄 |
| 6 | 包裝入庫 | 檢驗合格後 | 現場操作員 | 包裝紀錄 |

表單與欄位（欄位型別為 B 現有的 text、integer、decimal、boolean、date）：

| 表單 | 欄位（型別，是否識別鍵） |
|---|---|
| 領料單 | 批號（text，鍵）、工單號（text）、領料數量（decimal）、領料日期（date） |
| 配料紀錄 | 批號（text，鍵）、原料 A 實際重量（decimal）、原料 B 實際重量（decimal） |
| 混合紀錄 | 批號（text，鍵）、混合時間（integer）、混合完成（boolean） |
| 檢驗紀錄 | 批號（text，鍵）、檢驗值（decimal）、檢驗日期（date） |
| 包裝紀錄 | 批號（text，鍵）、包裝數量（integer） |

共用鍵「批號」可作為表單關聯的示範（沿用現有 shared-key 關聯）：依序建立 領料單到配料紀錄、配料紀錄到混合紀錄、混合紀錄到檢驗紀錄、檢驗紀錄到包裝紀錄 共 4 條，兩端皆為「批號」，來源標為 user。欄位單位不在 B 的欄位型別內，單位與數值規則留待整合階段（M06）由使用者指定，範例不提供。

「領料」節點不設表單：既有模型規定一張表單只屬於一個節點（`integrityErrors`），領料所需資料已在「開立領料單」填寫。因此共五個節點有表單、五張表單、一對一，領料節點的 formId 為空。

## 5. 已決定（2026-10-16，D99）

1. 提供「載入範例」按鈕，並同時提供輸入框提示文字。
2. 提示文字可由使用者關閉。
3. 範例資料同時作為整合 fixtures 的 B 側通用來源。

由此衍生的設計約束：

- 載入範例只新增、不覆蓋：新增 id 固定為 `example-` 開頭的範例工廠（沿用 B 的 id 格式 `^[a-z0-9-]+$`），名稱標示「範例」。已存在時按鈕改為提示並不重複新增。
- 清除範例只移除 `example-` 開頭的工廠及其生產邏輯、表單、關聯，且沿用現有的頁內刪除確認，不使用 `window.confirm`。
- 不修改任何 schema；範例文件須通過現有 `integrityErrors`，可匯出再匯入且內容相等。
- 提示開關的狀態只存在使用者瀏覽器的 localStorage（讀寫皆 try/catch，取不到時預設顯示提示），不進文件、不進匯出。
- 範例與提示文字不得含來源案例的任何專有詞彙或數值。
