# runtime-settings-kit 參數設定中心

來源：場域系統 S2（真名對照不在 repo，D-A4）原本沒有這個模組——設定散在各功能的程式碼與設定檔裡。這是依需求新增的 Kit：讓現場在系統上線後調整各功能願意開放的參數。拆分總表見 `docs/s2-kit-split.md`。

## 提供

- **有效值的四層優先順序**：場域鎖定 > 上線後調整 > 組裝期設定 > 功能預設。每個值都標示來源（「由場域鎖定」「上線後調整」「系統設定」「功能預設」）。
- **場域鎖定**：固定某個值，或收窄可調範圍（只能收窄，不能放寬到超過參數定義的範圍）。下層的值若不在目前範圍內會被略過，退回更下層，系統不會運作在不合規的值上。
- **參數定義**：型別（開關、數字、文字、選項）、單位、範圍、是否整數、風險（低／中／高）、誰能改。規則：operator 與 audit 永遠不能改；品管只能改低風險；高風險只限管理者。
- **修改的檢查順序**：參數存在 → 此角色可改 → 值合法（含場域範圍）→ 原因（依風險，預設中風險以上必填）→ 版本沒被別人改過（樂觀鎖）→ 寫入與記錄 → 提交後才通知各 Kit 套用。
- **變更紀錄**：只增不改，記下誰、何時、舊值、新值、原因與版本。還原也留紀錄，版本號單調遞增。
- **需要開發或資料庫遷移的項目**（例如改欄位型別）可以登錄成 `migration`／`extension`，只在清單裡說明做法，不提供編輯。

## 與其他 Kit 的接點

| 接點 | 做法 |
|---|---|
| 其他 Kit 登錄參數 | 在自己的啟動流程裡偵測到 `app.core.runtime_params` 才登錄（`register_param(ParamDef, apply)`）；本 Kit 不認得它們 |
| 套用變更 | 提交後同步呼叫各參數的 `apply(新有效值)`；啟動時 `apply_all` 把目前有效值同步一次 |
| 場域鎖定 | 啟動設定 `siteLocks`；指到未登錄的參數會直接報錯，避免打錯字讓安全限制默默失效 |

目前已登錄參數的 Kit：報警（3 項）、設備點檢（3 項）、儀表板（2 項）、批次生產（1 項），共 9 項，用來驗證機制；其他設定可依需要逐項開放。

## 已知限制

- 多個程序同時運作時，變更只會立刻套用到處理該請求的程序，其他程序要等重啟或呼叫 `apply_all` 重新載入。
- 目前沒有前端；介面版面見互動原型的「參數設定」。
- 參數值只支援單一純量（開關、數字、文字、選項），不含清單或表格結構。

## 設定

啟動時 `enable_runtime_settings_kit(raw)`（請在所有其他 Kit 之後），再於資料表建立後 `apply_all(db)`。鍵：`siteLocks`、`requireReasonFrom`（never／high／medium／all，預設 medium）。

## 驗證狀態

純函式核心（定義檢查、四層、權限與原因、登錄與通知、設定）有 24 項測試，另外四個 Kit 各有 3 項登錄與套用測試（兩個 Kit 同時載入時才執行，單獨載入時略過）：

    PYTHONPATH=kits/runtime-settings-kit/src/backend python -m unittest discover -s kits/runtime-settings-kit/tests

驗證狀態：純函式有單元測試；資料庫與 HTTP 由 `tests/s2-kits-integration` 實跑（七個 Kit 組成一個 FastAPI 應用程式，SQLAlchemy 非同步 + 記憶體 SQLite）。尚未在 PostgreSQL 與基線 platform-core 上實跑。
