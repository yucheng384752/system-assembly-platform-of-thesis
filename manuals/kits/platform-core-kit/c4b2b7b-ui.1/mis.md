## 用途

支援系統啟動、授權檢查、健康檢查與功能介面查詢。系統以容器方式運作：資料庫、後端、前端代理與授權守門容器。

## 前置條件

安裝主機需有 Docker 與 Docker Compose，並由系統管理人員使用可執行 Docker 與 sudo 的帳號安裝。本功能沒有相依其他功能。實測環境為 Ubuntu 22.04、Docker 29.1.3、Compose 5.6.0。映像體積依所選功能而定，「製造數據分析」一項約 2.5 GB，安裝前請確認磁碟剩餘空間遠大於所有映像的總和（建置與載入期間需要數倍空間）。

### 進階
安裝宣告要求 Python，安裝順序為 10；環境變數清單為空，實際需要的值由安裝輸入檔提供（見下一節）。

## 可設定項目

安裝時以輸入檔提供下列值，輸入檔需限制為僅管理者可讀：資料庫帳號、資料庫名稱、資料庫密碼、後端金鑰（SECRET_KEY）、權限功能的簽章金鑰（ENTRY_PERMISSION_JWT_SECRET）、預設租戶代號，以及第一個管理員的帳號、密碼與顯示名稱。選用「訂閱服務串接」時另需訂閱通知密鑰。這些值安裝後以秘密檔掛入容器，不會寫在設定或指令列。授權驗證需要組裝時嵌入發行者公鑰；保留佔位值時所有授權都會被拒絕。

## 操作步驟

依序執行安裝引擎的子命令（實測順序）：

1. `verify`：驗證系統包的簽章與根金鑰指紋。
2. `issue-license`：用發行者子金鑰簽發綁定本機硬體的授權檔，須指定到期時間。
3. `plan`：產出安裝計畫並得到計畫雜湊。
4. `apply`：帶入計畫、計畫雜湊、授權檔與安裝輸入檔，執行 11 個步驟，最後一步為健康檢查。實測 5 種組合的安裝時間為 32 秒至 169 秒，同時安裝 5 個選配功能為 153 秒。
5. 安裝完成後，前端代理預設只綁定本機的 8080 埠（127.0.0.1:8080）。從其他電腦使用時需另行設定對外的反向代理與加密連線；本次沒有驗證。
6. 引擎另有 `status` 與 `rollback` 子命令；本次實測沒有執行這兩個，實測的移除方式是停止並刪除該系統的容器、資料卷與安裝目錄。

請以預設的檔案建立遮罩（umask 022）執行安裝。引擎解壓檔案時沿用呼叫者的遮罩，在 umask 077 下，後端讀不到系統清單檔，授權檢查被誤報為「manifest-missing」，健康檢查逾時而失敗。這是已知問題，修正方式待決定。

## 輸入輸出

輸入授權文件與上述安裝輸入檔；授權驗證結果含有效狀態、客戶代稱、到期時間與失敗原因。

### 進階
契約宣告健康檢查為 GET /healthz，回 200 表示後端運作。

## 常見錯誤與復原

- 授權檢查會回報缺少授權檔、缺少密碼學套件、簽章錯誤、到期或機器識別不符。授權綁定硬體，換機器需重新簽發。
- 健康檢查逾時：先確認是否在 umask 077 下安裝，再看容器狀態與後端日誌。
- 安裝中途某一步失敗，引擎會還原該步驟（實測健康檢查失敗時如此）；整次安裝的 `rollback` 本次未驗證。
- 磁碟不足會使建置或載入映像失敗；清理未使用的映像與建置快取後再試。
- 自動修復與回復舊授權程序尚未提供。
